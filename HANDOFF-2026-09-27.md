## 5. Ops traps found the hard way (read before deploying)

1. **Two Pages projects, one source.** `createstuff.ai` = `createstuff-marketing`, and
   `app.createstuff.ai` = **`createstuff-app`**, both built from `apps/createstuff-marketing`.
   Deploy only one and half the fleet is stale — that is exactly how the GitHub fix went live on one
   domain and not the other. Always run both:
   `./deploy.sh pages createstuff-marketing apps/createstuff-marketing` **and**
   `./deploy.sh pages createstuff-app apps/createstuff-marketing`.
2. **The verify gate can report `FAILED` from a propagation race** (upload succeeded, edge still
   serving the previous copy). Re-check with a cache-busted curl before redeploying.
3. **Same-hash navigation does not reload** — the browser keeps the old bundle. Use `browser.reload`
   after a deploy or you will test yesterday's code (this produced one confusing "fix didn't work"
   read before it was caught).
4. **Relay restart recipe is unchanged** (see `HANDOFF-2026-09-25.md` §9): `setsid nohup env
   HIVE_TOKEN=$(cat .secrets/hive-token) HIVE_PORT=8787 node hive/hive-relay.js > .jobs/relay.log`
   + `cloudflared tunnel --url http://127.0.0.1:8787`, then **re-put `HIVE_URL` on both workers** —
   the hostname is random per restart.
5. **Never adopt fashionistas source from `fashionistas.ai`.** The zone runs email obfuscation at
   the edge, so the response is a *different file*: `mailto:` becomes `/cdn-cgi/l/email-protection#…`
   and an `email-decode.min.js` script tag is injected (**+257 B**). Copying it bakes edge tooling
   into the repo. Raw source is `https://fashionistas-ai.pages.dev/` — which is also what
   `deploy.sh verify_pages` compares against, so the sha gate only works against that copy.
6. **The fashionistas deploy tree has files that exist nowhere in git history.** A Pages deploy
   replaces the whole tree, and the footer links to `/fees/` `/contact/` `/about/` `/privacy/`
   (plus their stylesheet `/site.css`). They are now in `apps/fashionistas/`, along with `_headers`
   reproducing live's three observed headers. Drop any of them and the deploy deletes a live page.
7. **`canonCategory` is the single gatekeeper for categories — on INSERT, on PUT and on read.**
   It accepted only the seven pre-tree flat words, so every tree path became `NULL`: sellers'
   subcategories evaporated on save, edits never stuck, reads blanked them again, and half the
   departments could never be filled. New places live in `TAX_TREE` there; **keep it in sync with
   `TAX` in `apps/fashionistas/index.html`** (unknown values must keep returning `null`).
8. **Screen paints are serialised on purpose** (`enqueuePaint` in the app). Every render awaits a
   fetch, so parallel renders raced and the *slowest* one won — Home could repaint over the Shop
   you had just asked for. Do not "optimise" them back into parallel. Likewise `.dm-compose`
   reserves 54px so the floating tour button `#hc-fab` cannot sit on top of **Send**: a fixed
   control over an in-flow action silently eats taps, and `document.elementFromPoint()` on the
   button's centre is how that was caught (it returned `#hc-fab`, not the button).
